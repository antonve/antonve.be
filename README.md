# antonve.be

A static [Astro](https://docs.astro.build/) site styled with Tailwind CSS 4. It
ships HTML, CSS, self-hosted fonts, and images, with no client-side JavaScript.

Use Node.js 24.22.1 and the pnpm version pinned in `package.json`.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev          # development server
pnpm build        # static output in dist/
pnpm typecheck    # astro check
```

## Writing a blog post

Add one `.md` or `.mdx` file per post to `src/content/blog/`. The file name
sets the URL: `hello-world.md` is served at `/blog/hello-world`. Each post
needs this frontmatter, which the build validates:

```yaml
---
title: Hello world
description: One sentence for search results and share previews.
date: 2026-10-25
---
```

Plain Markdown can include raw HTML. Use `.mdx` to import and render Astro
components inside a post. Components render at build time; never give one a
`client:*` directive. Images referenced by relative path are optimized during
the build. The Blog navigation link appears once at least one post exists, so
the first post changes every page's header; regenerate the screenshot
baselines in that change with `pnpm test:e2e --update-snapshots`.
Run `pnpm dev` and open `/blog/<file-name>` to preview a post while you write.

The production image (`Dockerfile`) builds the site and serves `dist/` with a
non-root nginx on port 3000; `nginx.conf` keeps extensionless URLs, redirects
trailing slashes, and returns a real 404 for unknown paths. Missing pages use
the site's navigation and typography; nginx serves a matching fallback for
500, 502, 503, and 504 errors while preserving each HTTP status. These error
pages work without JavaScript. Errors generated by an upstream proxy must be
configured in that proxy separately.

`pnpm test:e2e` builds and tests a fresh production image in Docker. It starts
its own containers on automatically assigned localhost ports, including an
isolated nginx fixture for 500/502/503/504 responses, then removes them. It
never reuses an existing server. Set `SITE_IMAGE` to test an image already
built from this checkout; CI uses this to test the exact image it publishes.

The browser image version comes from the pinned Playwright dependency.
`playwright-report/` and `test-results/` retain the HTML report, screenshots,
failure traces, and the tested image ID, revision, and static artifact size.
The revision comes from the image label; local builds mark uncommitted changes
with `-dirty`, and images without a revision label report `null`. Locally built
test images are removed after the run; supplied `SITE_IMAGE` images are retained.
The Docker build checks types and rejects JavaScript in the shipped output.
CI also records a full dependency audit, including build tooling, in a separate
non-blocking step that runs even when verification fails.

Tailwind 4 requires Safari 16.4+, Chrome 111+, or Firefox 128+. Font files,
fallback metrics, and the site's original colors are preserved across the
styling upgrade.

## Dependency maintenance

Run `corepack pnpm audit --json` to audit all production and development
dependencies in the lockfile without installing or building the site. The
separate **Dependency audit** workflow runs daily at 07:23 UTC on the default
branch and can be started from **Actions → Dependency audit → Run workflow**.
Advisories or registry errors fail the run. The JSON report is visible in the
log and retained as the `dependency-audit` artifact for 30 days, including on
audit failure. This workflow has read-only repository permissions and cannot
publish a production image.

The workflow becomes available after it reaches the default branch. GitHub
may delay scheduled runs and [disables schedules in public repositories after
60 days without activity](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule);
re-enable the workflow in Actions if that happens. Enable Actions failure
notifications in your GitHub notification settings to receive failed-run alerts.

[Dependabot](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference)
checks npm/pnpm dependencies, Docker images, and GitHub Actions weekly. Minor
and patch updates are grouped per ecosystem; the pre-1.0 npm dependencies
`@astrojs/check` and `sharp` group only patches. Other updates get individual
PRs, except TypeScript and Node type major upgrades, which are excluded from
routine proposals to keep TypeScript 6 and the supported Node 24 types aligned.
Review each PR and require passing CI before merging; no automatic merge is
configured.
Enable the dependency graph, Dependabot alerts, and Dependabot security updates
in repository settings for advisory-driven security PRs between version checks.
When reviewing Node updates, keep `.node-version`, both workflows, and the
Docker builder aligned on the supported Node 24 release.
